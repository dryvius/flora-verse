# FloraVerse 前端 Mock MVP 开发总指令

你现在是 FloraVerse 项目的前端技术负责人和资深 Vue3 工程师。

请先完整阅读项目中的产品文档，理解产品定位、V1.0 功能边界、核心数据模型、用户流程和业务规则。

## 一、项目目标

当前阶段只开发 FloraVerse 小程序前端，暂时不开发 Java 后端。

通过 Mock 数据和 Mock Service 完成产品的第一版 MVP，实现：

发现植物 → 拍摄/选图 → 模拟 AI 识别 → 用户确认 → 创建植物个体 → 加入植物谱 → 查看收藏。

## 二、技术要求

- Vue 3
- TypeScript
- uni-app
- Pinia
- 组件化开发
- 严格 TypeScript 类型约束
- 遵循项目已有技术选型和代码规范

不要擅自引入不必要的 UI 框架或复杂依赖。

## 三、架构要求

必须采用数据访问抽象设计：

页面层 → 业务 Service 层 → Repository 接口层 → Mock Repository。

具体要求：

1. 页面禁止直接引用 Mock 数据。
2. 页面禁止直接操作 Mock 数组。
3. 业务逻辑放入 Service 层。
4. Mock Repository 实现统一的数据接口。
5. 为未来 HTTP Repository 预留实现位置。
6. 所有数据模型使用统一 TypeScript 类型。
7. Mock 数据结构应尽可能与未来 Java API DTO 保持一致。
8. 通过配置切换 Mock 和 HTTP 数据源。
9. Mock 模式下的数据变更应具有持久性，刷新或重新进入小程序后仍然可以读取。
10. 不能将 Mock 实现细节泄漏到页面组件中。

## 四、核心领域模型

遵循项目文档中的领域设计：

- PlantSpecies：标准植物物种。
- PlantInstance：用户独立收藏的植物个体。
- PlantCapture：一次收录记录。
- RecognitionTask：植物识别任务。

必须严格区分物种与个体：

同一个物种可以被多次收录，每次收录生成独立的 PlantInstance。

## 五、开发要求

按照以下顺序逐步开发：

1. 阅读文档并分析现有项目。
2. 检查项目目录和技术配置。
3. 提出前端架构和目录调整方案。
4. 定义 TypeScript 类型和 API 契约。
5. 实现 Mock 数据和 Repository。
6. 实现首页。
7. 实现植物收录完整流程。
8. 实现植物谱和收藏列表。
9. 实现物种详情与个体详情。
10. 实现个人中心和收藏统计。
11. 完成全流程测试。

不要跳过架构设计，直接开始大量生成页面。

## 六、开发规范

- 每个阶段完成后进行类型检查和必要的构建检查。
- 不允许使用大量 any。
- 不允许在页面中硬编码业务 Mock 数据。
- 不允许为了演示效果破坏领域模型。
- 不允许未经确认擅自增加 V1.0 范围外的功能。
- 所有页面必须考虑加载、空数据、失败和异常状态。
- 图片资源需要统一管理。
- 业务操作需要考虑重复提交和幂等性。
- 重要业务流程应提供可测试的 Service 方法。
