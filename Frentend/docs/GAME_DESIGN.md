# FloraVerse V1.0 核心玩法设计

-   文档状态：初稿
-   范围：植物发现、识别、收录、收藏和图鉴
-   不包含：养成、战斗、联机和交易

## 1. 设计目标

让用户通过低门槛、可重复的流程，把现实中看到的植物转化为有记录价值的数字收藏。

核心体验需要满足：

-   操作简单：拍摄或选图即可开始。
-   结果可信：识别结果允许确认和纠错。
-   收藏有意义：每次收录有独立记录。
-   图鉴可积累：新物种与重复个体有不同统计意义。
-   真实友好：不鼓励采摘、破坏或冒险寻找植物。

## 2. 核心循环

发现 → 拍摄 → 识别 → 确认 → 收录 → 收藏 → 浏览与记录 → 再次发现。

## 3. 植物身份体系

### 3.1 PlantSpecies：物种

代表植物学意义上的标准物种。物种数据应来自经过整理的植物知识库，不由每次
AI 识别结果直接创建。

建议字段：

-   内部物种 ID
-   接受学名（scientific name）
-   中文标准名
-   常用名/别名
-   科、属
-   植物分类标签
-   简介与形态特征
-   参考图片
-   数据来源、版本和审核状态

### 3.2 PlantInstance：植物个体

代表用户的一次独立收藏。每次收录成功创建一个新的个体。

建议展示字段：

-   收藏编号
-   关联物种
-   用户自定义昵称（可选）
-   本次拍摄照片
-   收录时间
-   首次发现/重复发现标记
-   用户备注（可选）

个体不是现实植物的生物学个体鉴定。产品不应宣称能够证明两张照片拍摄的是同一株真实植物。

### 3.3 PlantCapture：收录记录

记录一次完整的收录操作，包括图片、识别候选、最终确认物种、时间和处理状态。

一个收录流程只能成功创建一个
PlantInstance。网络重试必须通过幂等键防止重复创建。

## 4. 收录规则

### 4.1 开始收录

用户可以： - 打开相机拍摄 - 从相册选择照片

基础图片要求： - 图片中应有清晰可见的植物主体。 -
不支持的文件格式或过大文件应给出明确提示。 -
图片质量不足时，允许用户重新拍摄。

### 4.2 识别处理

识别服务返回： - 主要候选物种 - 其他候选物种（如有） -
识别解释或特征（如服务支持） -
置信度（仅在供应商定义清楚且可合理展示时） - 任务状态和错误信息

不能把模型置信度等同于科学鉴定结论。

### 4.3 用户确认

用户可以： - 确认主要候选 - 选择其他候选 - 搜索并手动选择物种 -
重新拍摄 - 取消本次收录

如果系统无法匹配到物种库中的标准记录，应允许进入"待确认/未收录物种"流程，而不是随意创建重复物种。

### 4.4 收录成功

服务端执行： 1. 校验用户身份和识别任务状态。 2. 校验最终物种 ID 有效。
3. 检查幂等键。 4. 查询用户是否已发现该物种。 5. 创建 PlantCapture。 6.
创建 PlantInstance。 7. 更新或计算用户图鉴统计。 8.
返回首次发现状态和收藏详情。

上述关键写入应处于一致性事务或具有可靠补偿机制。

## 5. 首次发现与重复发现

-   首次发现：该用户此前没有成功收藏过该物种。
-   重复发现：该用户已收藏过该物种，但本次收录仍创建新的个体。
-   物种图鉴数量：按不同 speciesId 去重。
-   个体收藏数量：按有效 PlantInstance 数量统计。
-   收录历史数量：按成功 PlantCapture 数量统计。

示例：

用户先后收录绿萝三次： - 已发现物种：1 - 收藏个体：3 - 成功收录记录：3

## 6. 图鉴设计

### 6.1 两种浏览视图

**物种图鉴** - 每个物种只出现一次。 - 展示物种名称、代表图和发现状态。 -
点击进入标准物种档案。 - 可以查看该物种下自己收藏的所有个体。

**个体收藏** - 每次成功收录独立展示。 - 支持按时间排序。 -
点击进入本次收录档案。 - 可以查看原始照片、收录时间和用户备注。

### 6.2 物种详情

建议内容： - 中文标准名、学名和别名 - 科、属、分类信息 - 植物简介 -
形态特征 - 生长环境（有可靠数据时） - 用户已收藏个体数量 -
用户首次发现时间 - 该物种的个人收录记录

### 6.3 个体详情

建议内容： - 本次拍摄照片 - 关联物种 - 收录时间 - 首次/重复发现 -
识别结果与用户确认结果 - 用户备注 - 删除收藏入口

## 7. 收藏标签与成就

V1.0 推荐使用不影响战斗数值的收藏标签：

-   首次发现
-   重复发现
-   新科发现
-   新属发现
-   连续探索（如未来加入连续记录）
-   特定分类收集成就

不建议 V1.0 引入 N/R/SR/SSR
等战斗导向稀有度。现实物种保护等级、自然分布稀有程度和游戏收藏稀有度是不同概念，不能混为一谈。

## 8. 植物数据质量原则

-   物种标准名和学名应有可追溯数据来源。
-   学名可能发生分类修订，应支持别名、异名和分类版本。
-   AI 候选必须映射到标准物种库，避免重复物种。
-   用户纠错不能直接修改公共物种主数据。
-   未收录物种进入审核或待补充流程。
-   不能仅凭单张照片断言植物健康状态、毒性或可食用性。

## 9. 后续扩展原则

未来可扩展： - 植物成长阶段 - 游戏属性和技能 - 变异外观 - 植物园展示 -
战斗阵容 - 社交分享

这些内容应作为后续独立模块，不影响 V1.0 的物种、个体和收录记录基本关系。
