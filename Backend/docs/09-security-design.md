# 09 - 安全、隐私与反作弊设计

## 1. 服务端权威

以下数据只能由服务端决定：
- 用户身份和角色。
- 捕捉是否成功。
- 植物个体创建。
- 经验、等级和成长阶段。
- 基础属性、环境加成和最终属性。
- 战力和排行榜统计。
- AI 生成配额和扣次。

客户端提交的 userId、attack、level、experience、power 等字段一律不能作为可信输入。

## 2. 认证与授权

- 所有个人数据接口要求认证。
- 每次读取/修改资源都校验资源归属。
- 管理员接口使用独立角色和权限。
- Access Token 短期有效。
- Refresh Token 可轮换、可撤销。
- 防止 IDOR（通过猜测其他用户资源 ID 访问数据）。

## 3. API 防护

- DTO 白名单校验。
- 请求体大小限制。
- 用户级和 IP 级限流。
- 登录、上传、识别、生成接口单独限流。
- 统一错误处理，不泄露堆栈。
- CORS 和小程序域名策略按部署场景配置。
- 记录 requestId，日志中不记录 Token、AppSecret、原图 URL 签名。

## 4. 图片安全

- 限制文件类型、尺寸和大小。
- 校验文件魔数/实际内容。
- 生成随机对象 key。
- 防止路径穿越和覆盖。
- 原始照片默认私有。
- 生成图像和用户上传图片经过适当内容安全检查。
- 处理 EXIF 等元数据，避免无意暴露精确位置。
- 生成内容发布前按产品策略审核。

## 5. 游戏反作弊

- 捕捉任务只能消费一次。
- 经验和战力不能由客户端指定。
- 排行榜基于服务端数据。
- 关键请求加幂等键。
- 对异常频率、异常坐标、短时间大量捕捉进行风控记录。
- 环境加成使用服务端天气/规则快照，不接受客户端自报天气作为唯一依据。

## 6. 地理位置隐私

- 只有实现功能确有必要时才申请位置权限。
- 明确说明用途。
- 精确经纬度不入库。
- 当前营地环境沿用前端 `resolveCampWeatherStation`：按月份选择预设天气和 `bonusPercent`，再用 `applyClimateCombatBonus(baseCombatPower, bonusPercent)` 在读取时得到展示战力。
- 该结果不写回 `PlantSpecies.baseCombatPower`，也不写入 `PlantInstance.combatPower`。
- 若未来做地理探索，单独设计位置模型，不把坐标补进现有收录表。
- 不把精确位置写入普通应用日志。

## 7. 中国大陆上线检查

上线前由项目负责人结合实际业务和主体情况核实：
- ICP 备案及必要的其他许可/备案要求。
- 微信小程序平台规则、服务器域名和隐私保护指引。
- 个人信息保护、数据安全和网络安全相关义务。
- 用户隐私政策、服务协议和个人信息收集清单。
- 生成式 AI 服务相关管理要求及生成合成内容标识要求。
- AI 服务商备案/登记、商用授权、内容审核和数据处理条款。
- 图片、植物数据和第三方内容的版权/许可。

本文件是工程检查清单，不构成法律意见。实际适用要求应根据运营主体、服务模式和届时有效规定核实。
