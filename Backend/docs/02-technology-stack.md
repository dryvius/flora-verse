# 02 - 技术选型与成本策略

## 1. 技术栈决策

| 层次 | 选型 | V1 决策 |
|---|---|---|
| 小程序 | 现有 Vue 3 + TypeScript 工程 | 沿用，不因后端重构前端 |
| 后端 | NestJS + TypeScript | 采用 |
| API | REST + OpenAPI/Swagger | 采用 |
| 数据库 | MySQL 8.x | 采用 |
| ORM | Prisma | 采用 |
| 文件存储 | 腾讯云 COS 或兼容对象存储 | 上云时采用 |
| 本地环境 | Docker Compose | 采用 |
| 异步任务 | MySQL 持久化任务表 + Worker | V1 采用 |
| 缓存 | Redis | 暂缓 |
| 队列 | BullMQ | 暂缓，未来可升级 |
| 反向代理 | Nginx | 上云时采用 |
| 部署 | 单台国内云服务器 + Docker Compose | MVP 采用 |

版本号应在项目初始化时选用当时仍受支持的 Node.js LTS、NestJS、Prisma 和 MySQL 版本，并锁定依赖版本。不要在文档中长期固定一个可能过期的 patch 版本。

## 2. 为什么选择 NestJS

- 与前端共享 TypeScript 语言和类型思维。
- 模块、Provider、依赖注入适合组织业务边界。
- DTO、Guard、Pipe、Interceptor 等机制适合构建规范 API。
- Swagger 可生成接口契约，方便 Cursor 和前端联调。
- 可以在同一代码仓库中运行 API 与 Worker。

NestJS 不是“自动保证架构正确”的工具。模块边界、事务、权限、业务规则仍需开发者设计和测试。

## 3. 为什么选择 MySQL + Prisma

FloraVerse 具有用户、物种、科属、捕捉、个体、收藏、好友和任务等强关系数据，MySQL 适合作为核心数据源。

Prisma 提供：
- Schema 管理。
- 类型安全查询。
- Migration。
- 事务 API。

复杂排行榜查询、批量更新或性能敏感查询可以使用经过审查的 SQL，不必强行全部用 ORM 表达。

## 4. 低成本策略

### 本地开发阶段

- 使用 Docker Compose 启动 MySQL。
- 任务队列使用 MySQL 表。
- AI 使用供应商 API，不自建模型。
- 图片开发阶段可使用本地 S3 兼容存储或 Mock Storage；正式小程序上传前接入 COS。
- 暂不购买 Redis、CDN、独立数据库实例。

### 小规模线上 MVP

可评估单台国内 CVM 运行：
- Nginx
- NestJS API
- NestJS Worker
- MySQL（仅预算非常有限时短期同机）
- Redis 暂不部署

生产环境应优先考虑托管 MySQL、自动备份和恢复演练。若数据库同机部署，必须明确这是成本折中，并做好异机备份。

### 何时引入 Redis/BullMQ

满足以下任一情况时再评估：
- 任务领取出现明显数据库竞争。
- Worker 需要复杂优先级、延迟任务或高并发重试。
- 需要多个 Worker 实例横向扩展。
- 排行榜或热点读缓存成为瓶颈。

## 5. AI 成本控制

用户选择了实时生成模式，生成费用会随每次生成请求发生。必须实施：
- 每用户每日生成次数上限。
- 用户级并发限制。
- 任务幂等键，防止重复点击产生多次收费。
- 生成前展示成本/次数规则（如产品需要）。
- 失败重试次数上限。
- 记录 Provider、模型、参数、耗时、供应商请求 ID 和计费信息（供应商可提供时）。
- 管理端预算告警与全局熔断开关。

不要默认在每次生成时自动重试多次，因为供应商可能已经计费但客户端超时。

## 6. 供应商选型验证清单

AI 供应商正式选定前，必须验证：
1. 中国大陆网络可访问性。
2. API 是否开放给当前账号和主体。
3. 价格、计费单位、失败请求是否计费。
4. 并发、速率限制和超时策略。
5. 图片尺寸、格式、内容限制。
6. 参考图/图生图能力。
7. 商业使用授权及生成内容权利。
8. 数据是否用于模型训练及相关设置。
9. 内容安全审核机制。
10. 生成合成内容标识和平台合规责任。

不得将“优先测试”写成“已经确定可用”。
